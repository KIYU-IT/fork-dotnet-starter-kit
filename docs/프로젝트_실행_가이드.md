## Visual Studio 2022 실행 방법

### 🎯 권장 방법 (가장 쉬움)

#### Step 1: PostgreSQL 준비

**방법 A: Docker Compose 사용 (권장) 🌟**

`compose` 디렉토리로 이동 후:

```powershell
# PowerShell
cd D:\.NET\fork-dotnet-starter-kit\compose

# PostgreSQL 시작
docker-compose -f docker-compose.db.yml up -d

# 상태 확인
docker-compose -f docker-compose.db.yml ps

# 중지 (필요시)
docker-compose -f docker-compose.db.yml down
```

**장점**:
- ✅ 설정이 파일로 관리됨
- ✅ 헬스체크 자동 포함
- ✅ 재시작 정책 자동 적용
- ✅ 한 번만 실행하면 자동 재시작

**방법 B: Docker run 명령어**

```powershell
# PostgreSQL 컨테이너 실행 (처음 한 번만)
docker run -d `
  --name fsh-postgres `
  -e POSTGRES_USER=admin `
  -e POSTGRES_PASSWORD=admin `
  -e POSTGRES_DB=fullstackhero `
  -p 5434:5432 `
  postgres:16

# 이미 생성했다면 시작
docker start fsh-postgres

# 상태 확인
docker ps | findstr fsh-postgres
```

#### Step 2: 솔루션 열기

1. Visual Studio 2022 실행
2. **파일** → **열기** → **프로젝트/솔루션**
3. `D:\.NET\fork-dotnet-starter-kit\src\FSH.Starter.sln` 선택

#### Step 3: 시작 프로젝트 설정

**솔루션 탐색기**에서:
```
aspire/Host 프로젝트 우클릭
→ "시작 프로젝트로 설정"
```

✅ 프로젝트 이름이 **굵게** 표시되면 완료

#### Step 4: 데이터베이스 초기화

**✅ 자동 실행 (권장)**

애플리케이션을 처음 실행하면 **자동으로** 다음 작업이 수행됩니다:

1. **마이그레이션 자동 적용**:
   - Identity 스키마 (사용자, 역할, 권한)
   - Tenant 스키마 (멀티테넌시)
   - Catalog 스키마 (제품 카탈로그)
   - Todo 스키마 (할일 목록)

2. **초기 데이터 자동 생성**:
   - Root 테넌트 생성
   - 기본 역할 (Basic, Admin) 생성
   - 관리자 계정 생성 (테넌트별)
   - 샘플 제품 1개
   - 샘플 할일 1개

**로그 확인**:
```
Application startup complete.
→ Tenant Store initialized.
→ Identity schema migrated.
→ Default roles seeded.
→ Admin user created.
→ Catalog schema migrated.
→ Todo schema migrated.
```

**💡 팁**: 첫 실행 시 마이그레이션으로 인해 시작이 조금 느릴 수 있습니다 (약 10-20초).

---

**🔧 수동 실행 (선택사항)**

자동 마이그레이션을 원하지 않거나 문제가 있을 경우:

**방법 1: Package Manager Console**

```powershell

cd src/api/server

Update-Database -Context IdentityDbContext
Update-Database -Context TenantDbContext
Update-Database -Context CatalogDbContext
Update-Database -Context TodoDbContext
```

**방법 2: 통합 터미널**

```powershell

cd D:\.NET\fork-dotnet-starter-kit\src\api\server

dotnet ef database update --context IdentityDbContext
dotnet ef database update --context TenantDbContext
dotnet ef database update --context CatalogDbContext
dotnet ef database update --context TodoDbContext
```

**확인**:
```powershell
# PostgreSQL 테이블 확인
docker exec -it fsh-postgres psql -U admin -d fullstackhero -c "\dt"

# 출력: identity, tenant, catalog, todo 스키마의 테이블들
```

#### Step 5: 실행! 🚀

**방법 1: 디버그 모드 실행**
- 키보드: `F5`
- 또는 상단 툴바: 녹색 ▶️ **Host** 버튼 클릭

**방법 2: 디버그 없이 실행** (더 빠름)
- 키보드: `Ctrl + F5`

#### Step 6: 브라우저 자동 열림

실행하면 자동으로 다음 주소들이 열립니다:
- 🎛️ Aspire Dashboard: `https://localhost:7200`
- 🔧 API Swagger: `https://localhost:7000/swagger`
- 🖥️ Blazor 앱: `https://localhost:7100`

### 빠른 실행 스크립트

#### Windows (PowerShell)

`start.ps1` 파일 생성:

```powershell
# start.ps1
Write-Host "🚀 FSH Starter Kit 실행 중..." -ForegroundColor Green

# PostgreSQL 확인 및 시작
$postgres = docker ps -a --filter "name=fsh-postgres" --format "{{.Names}}"
if ($postgres -eq "fsh-postgres") {
    Write-Host "📦 PostgreSQL 시작 중..." -ForegroundColor Yellow
    docker start fsh-postgres
    Start-Sleep -Seconds 5
} else {
    Write-Host "📦 PostgreSQL 생성 중..." -ForegroundColor Yellow
    docker run -d `
      --name fsh-postgres `
      -e POSTGRES_USER=admin `
      -e POSTGRES_PASSWORD=admin `
      -e POSTGRES_DB=fullstackhero `
      -p 5434:5432 `
      postgres:16
    Start-Sleep -Seconds 10
}

# 프로젝트 실행
Write-Host "🎯 Aspire 시작 중..." -ForegroundColor Cyan
Set-Location -Path "D:\.NET\fork-dotnet-starter-kit\src\aspire\Host"
dotnet run
```

**실행**:
```powershell
.\start.ps1
```

## 로그인 정보

### 기본 관리자 계정

프로젝트가 처음 실행되면 기본 관리자 계정이 자동으로 생성됩니다.

```

비밀번호: 123Pa$$word!
```

**권한**: 모든 기능 및 관리자 패널 접근 가능

### 추가 테스트 계정 (Seeded Data)

```
사용자 1:
이메일: user@example.com
비밀번호: User1234!

사용자 2:
이메일: demo@example.com
비밀번호: Demo1234!
```

### API 토큰 발급

#### curl 사용

```bash
# 1. 토큰 요청
curl -X POST https://localhost:7000/api/v1/tokens \
  -H "Content-Type: application/json" \
  -d '{
    "email": "admin@root.com",
    "password": "123Pa$$word!"
  }' \
  --insecure

# 2. 응답
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "abc123...",
  "tokenExpirationInMinutes": 60,
  "refreshTokenExpirationInDays": 7
}

# 3. 토큰으로 API 호출
curl https://localhost:7000/api/v1/catalog/products \
  -H "Authorization: Bearer eyJhbGc..." \
  --insecure
```

#### PowerShell 사용

```powershell
# 토큰 요청
$body = @{
    email = "admin@root.com"
    password = "123Pa`$`$word!"
} | ConvertTo-Json

$response = Invoke-RestMethod -Uri "https://localhost:7000/api/v1/tokens" `
  -Method Post `
  -Body $body `
  -ContentType "application/json" `
  -SkipCertificateCheck

$token = $response.token

# API 호출
Invoke-RestMethod -Uri "https://localhost:7000/api/v1/catalog/products" `
  -Headers @{ Authorization = "Bearer $token" } `
  -SkipCertificateCheck
```

#### Swagger UI에서 인증

1. Swagger 접속: `https://localhost:7000/swagger`
2. 우측 상단 **🔓 Authorize** 버튼 클릭
3. Value 입력란에 토큰 입력:
   ```
   Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
   ```
4. **Authorize** 버튼 클릭
5. **Close** 버튼 클릭
6. 이제 API 호출 가능! 🎉

## 문제 해결

### 1. "dotnet: command not found"

**원인**: .NET SDK가 설치되지 않았거나 PATH에 등록되지 않음

**해결**:
```bash
# .NET SDK 설치 확인
dotnet --version

# 설치되지 않았다면
# Windows: https://dotnet.microsoft.com/download 에서 설치
# Linux: sudo apt install dotnet-sdk-9.0
# macOS: brew install dotnet

# PATH 확인 (Linux/macOS)
echo $PATH | grep dotnet

# PATH에 추가 (Linux/macOS)
export PATH="$PATH:/usr/share/dotnet"
```

### 2. "Cannot connect to the database server"

**원인**: PostgreSQL이 실행되지 않았거나 연결 정보가 잘못됨

**해결**:
```bash
# PostgreSQL 컨테이너 상태 확인
docker ps | grep fsh-postgres

# 실행 중이 아니면 시작
docker start fsh-postgres

# 없다면 새로 생성
docker run -d \
  --name fsh-postgres \
  -e POSTGRES_USER=admin \
  -e POSTGRES_PASSWORD=admin \
  -e POSTGRES_DB=fullstackhero \
  -p 5434:5432 \
  postgres:16

# 로그 확인
docker logs fsh-postgres

# 연결 테스트
docker exec -it fsh-postgres psql -U admin -d fullstackhero -c "SELECT 1;"
```

### 3. "Port 7000/7100/7200 is already in use"

**원인**: 다른 프로세스가 이미 포트를 사용 중

**해결 (Windows)**:
```powershell
# 포트 사용 중인 프로세스 확인
netstat -ano | findstr :7000

# 프로세스 종료 (PID 확인 후)
taskkill /PID <PID> /F

# 또는 Visual Studio에서
# 디버깅 중지: Shift + F5
```

**해결 (Linux/macOS)**:
```bash
# 포트 사용 중인 프로세스 확인
lsof -i :7000

# 프로세스 종료
kill -9 <PID>

# 모든 dotnet 프로세스 종료
pkill dotnet
```

### 4. SSL 인증서 오류

**증상**: "ERR_CERT_AUTHORITY_INVALID" 또는 "SSL connection error"

**해결**:
```bash
# .NET 개발 인증서 신뢰
dotnet dev-certs https --trust

# 인증서 재생성 (문제 지속 시)
dotnet dev-certs https --clean
dotnet dev-certs https --trust

# Windows: 관리자 권한 필요
# macOS: 비밀번호 입력 필요
```

**Visual Studio**: 첫 실행 시 자동으로 인증서 신뢰 여부를 물어봅니다. "예" 클릭

### 5. "Unable to resolve service for type 'DbContext'"

**원인**: 의존성 주입 등록이 누락되었거나 마이그레이션이 실행되지 않음

**해결**:
```bash
# 1. 솔루션 정리 및 재빌드 (Visual Studio)
# 솔루션 → 솔루션 정리
# 솔루션 → 솔루션 다시 빌드

# 2. NuGet 패키지 복원
dotnet restore

# 3. 마이그레이션 재실행
cd src/api/server
dotnet ef database update --context IdentityDbContext
dotnet ef database update --context TenantDbContext
dotnet ef database update --context CatalogDbContext
dotnet ef database update --context TodoDbContext
```

### 6. "Failed to bind to address - address already in use"

**원인**: Aspire나 다른 프로젝트가 이미 실행 중

**해결**:
```bash
# 실행 중인 모든 dotnet 프로세스 확인
# Windows
tasklist | findstr dotnet

# Linux/macOS
ps aux | grep dotnet

# 모든 dotnet 프로세스 종료
# Windows
taskkill /IM dotnet.exe /F

# Linux/macOS
pkill dotnet
```

### 7. "The EF Core tools version ... is older than that of the runtime ..."

**원인**: Entity Framework Core 도구가 오래됨

**해결**:
```bash
# EF Core 도구 업데이트
dotnet tool update --global dotnet-ef

# 버전 확인
dotnet ef --version
# 출력: 9.0.0 이상이어야 함
```

### 8. 마이그레이션 실패

**증상**: "The entity type ... cannot be mapped to a table..."

**해결**:
```bash
# 데이터베이스 삭제 및 재생성 (주의: 모든 데이터 삭제됨)
cd src/api/server

# 각 컨텍스트별로 삭제
dotnet ef database drop --context IdentityDbContext --force
dotnet ef database drop --context TenantDbContext --force
dotnet ef database drop --context CatalogDbContext --force
dotnet ef database drop --context TodoDbContext --force

# 다시 생성
dotnet ef database update --context IdentityDbContext
dotnet ef database update --context TenantDbContext
dotnet ef database update --context CatalogDbContext
dotnet ef database update --context TodoDbContext
```

### 9. Blazor 앱이 API에 연결되지 않음

**원인**: API URL이 잘못 설정됨

**해결**:
```bash
# Blazor 설정 파일 확인
cat src/apps/blazor/client/wwwroot/appsettings.json

# API URL이 맞는지 확인
{
  "ApiBaseUrl": "https://localhost:7000"
}

# 필요시 수정
```

### 10. Docker Desktop이 실행되지 않음

**증상**: "Cannot connect to the Docker daemon"

**해결**:
- **Windows/macOS**: Docker Desktop 애플리케이션 실행
- **Linux**: `sudo systemctl start docker`
